# Totalmap

Whale에서 사용하는 네이버지도·카카오맵·Google 지도 개인 저장 목록 연결 도구.

현재 진행 상황과 다음 개발 순서는 [프로젝트 인수인계 및 작업 지침](docs/PROJECT_INSTRUCTIONS.md)을 참조하세요.

## 현재 상태

**개발 중이며 실제 지도 자동 동기화는 아직 작동하지 않습니다.**

- 구현: 네 분류 설정, 국내 장소의 최초 합집합/이후 추가·삭제·이동 계획, 충돌 감지, 기준 상태 검증, 로컬 관리 화면.
- 구현: 사용자가 실행한 지도 탭에서 현재 DOM의 장소 링크와 화면 구조를 읽는 **읽기 전용 진단 확장**. 0개 링크는 빈 목록 성공으로 처리하지 않고 읽기 미지원으로 표시합니다.
- 네이버 저장 패널에서는 진단으로 확인한 장소 카드 구조에 한해 `data-*` 속성 이름만 기록합니다. 값은 검증된 장소 ID 속성 허용 목록에 있는 경우에만 읽도록 제한하며, 현재 확인된 속성이 없어 그 목록은 비어 있습니다. 임의 `dataset` 값 수집은 하지 않습니다.
- 미검증/미구현: 서비스별 전체 목록 수집·계정/목록 ID 확인, 국가 판별, 서비스 간 장소 검색/매칭, 실제 추가·삭제·이동 실행, 주기 실행, 메모 발견/정리.
- 진단 링크는 저장 목록의 소속을 입증하지 않습니다. 검색/추천 링크가 섞일 수 있고, 링크 없이 표시된 장소와 다른 출처의 iframe은 읽지 못할 수 있습니다. 진단 결과는 항상 `complete: false`이고 동기화 스냅샷으로 자동 변환하지 않습니다.
- Google Places API 호출이나 비공개 API 호출은 사용하지 않습니다. 로그인 쿠키·토큰을 추출하지 않습니다.

## 확정된 범위

| 통합 분류 | 네이버 | 카카오 | Google |
|---|---|---|---|
| landmark | 내 장소 | 기본 그룹 | landmark |
| cuisine | cuisine | cuisine | cuisine |
| cafeteria | cafeteria | cafeteria | cafeteria |
| bar | bar | bar | bar |

- 각 서비스의 기존 목록 이름을 유지하며 ID로 연결합니다.
- 국내(KR) 장소만 전파합니다. 해외 및 국가 미확인 장소는 제외합니다.
- Google의 `Saved places`, `여행 계획`은 제외합니다.
- 기존 공유 목록에 추가하는 것은 사용자가 허용했습니다.
- 메모를 복사하지 않습니다. 기존 메모 삭제는 접근 난이도 검증 후 결정하며, 복잡하면 메모 있는 장소를 알립니다. 현재 진단 버전은 메모를 읽거나 삭제하지 않습니다.
- 첫 연결은 합집합, 기준 상태 확립 이후에는 사용자 변경을 전파합니다. 한 목록에서 제거해도 다른 분류 소속은 유지합니다.
- 자동화 자체의 변경은 작업 이력과 재조회로 구분해야 합니다. 실제 쓰기 실행기는 아직 연결되지 않았습니다.

## Whale 설치 (개발용 읽기 진단)

1. Whale 주소창에 `whale://extensions` 입력.
2. 개발자 모드에서 **압축해제된 확장앱 설치** 선택.
3. `C:\Users\yount\totalmap\extension` 폴더 선택.
4. 지도 전용 창의 네이버지도 탭에서 `cuisine` 등 대상 목록을 엽니다.
   네이버는 Totalmap 팝업의 **네이버 저장 패널 연결 (최초 1회)** 버튼으로 저장 패널 주소 접근을 허용해야 합니다.
5. Totalmap 확장 버튼 → 해당 분류 선택 → **현재 지도 읽기**.
6. **관리 화면 열기**에서 결과를 확인합니다. 카카오·Google도 각각 실행합니다.
7. 필요하면 **수집 결과 내보내기**로 진단 JSON을 저장합니다. 이름과 장소 링크를 포함하므로 개인 파일로 취급합니다.

설치된 앱에서 오류가 나면 표시된 메시지를 확인합니다. 개발 소스 변경 후에는 확장앱 관리자에서 새로고침한 뒤 팝업/관리 화면을 다시 엽니다.

권한은 `activeTab`, `scripting`, `storage` 세 가지입니다. 사용자가 누른 현재 탭의 페이지를 읽고 결과를 브라우저 로컬에 보관합니다. 지속적인 전체 사이트 접근, 비밀번호, 쿠키는 요구하지 않습니다. `activeTab`으로 접근할 수 없는 교차 출처 프레임은 후속 수집기 설계에서 별도로 검증해야 합니다.

개발 중 `node scripts/diagnostics.mjs`를 실행하면 확장의 읽기 버튼이 이 PC의 `127.0.0.1:47832`로 구조 진단을 전달합니다. 수신한 파일은 `.gitignore` 처리된 `data/diagnostics`에 저장합니다. 외부 서버로 전송하지 않습니다. 구조에는 화면에 표시된 장소명 등 텍스트가 포함되며, 로그인 입력 필드·스크립트·쿠키·스토리지·네트워크 응답은 수집하지 않습니다. 메모 편집/복사는 하지 않지만 목록 화면에 이미 표시된 메모 텍스트가 구조에 포함될 수 있습니다. 수신기가 꺼져 있거나 연결 실패 시 기존 내보내기를 사용할 수 있습니다.

공식 개발 설치 안내: https://developers.whale.naver.com/tutorials/debugging/
선택 권한: `pages.map.naver.com`, `pcmap.place.naver.com` 두 주소의 프레임 읽기. 팝업의 연결 버튼을 누를 때 브라우저가 권한을 요청하며, 거부하면 저장 패널 수집이 제한됩니다.

## 개발 및 화면 미리보기

Node.js 22 이상. 외부 패키지 설치가 필요 없습니다.

```powershell
npm.cmd test
npm.cmd run check
npm.cmd start
```

미리보기: http://127.0.0.1:47831

일반 웹 미리보기는 지도와 연결되지 않으며 localStorage를 사용합니다. 실제 확장 화면은 `chrome.storage.local`을 사용하므로 두 화면의 데이터는 별개입니다. 서버는 확장 폴더의 정적 파일만 제공합니다. 사용자 데이터 전송 API가 없습니다.

## 파일 구조

- `extension/core/engine.js`: 외부 부작용 없는 동기화 계획 및 기준 상태 생성.
- `extension/core/jobs.js`: 변경 전후 재조회·응답 유실 복구·이동 순서를 구현한 실행 프로토콜. 실제 지도 어댑터는 미연결.
- `extension/core/config.js`: 확정된 정책과 참고 수치.
- `extension/core/links.js`: 허용된 지도 URL에서 장소 식별자 정규화.
- `extension/capture.js`: 현재 로딩된 DOM 링크 진단. 완전한 목록 수집기 아님.
- `extension/popup.*`: 지도 탭에서 진단 실행.
- `extension/dashboard.*`: 수집 결과 및 스냅샷 계획 미리보기.
- `tests/`: 불완전 조회, 계정 변경, 충돌, 이동, 삭제, 해외 제외 등의 단위 검증.
- `docs/snapshot-contract.md`: 후속 서비스 어댑터의 입력 계약.

## 실제 환경에서 확인한 범위

2026-09-22: 로컬 Whale 실행 파일 버전 `4.39.410.14` 확인. 사용자 준비 창 제목 `저장 - 네이버지도 - Whale` 확인.

Windows 화면 읽기 도구가 `window id ... no longer belongs to Naver_Whale; current owner is Naver_Whale` 오류를 반환하여 실제 DOM/저장 목록은 아직 읽지 못했습니다. 단위 테스트 통과는 실제 서비스 자동화 성공을 의미하지 않습니다.

사용자가 확장을 설치한 뒤 전달한 최신 네이버 진단에서는 `pages.map.naver.com` 저장 패널과 `cuisine`의 표시 개수 718개를 확인했습니다. 안정적인 장소 ID와 전체 목록 수집은 아직 미검증입니다. 다음 단계는 확장을 새로고침하여 제한된 속성 이름 진단을 확인하고, 실제 장소 식별자를 검증하는 것입니다. 기존 지도 저장 내용은 변경하지 않았습니다.
