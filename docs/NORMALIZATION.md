## 새로 확보한 실제 근거

사용자가 네이버 cuisine 카드 한 개를 선택하고 제공한 주소창 URL의 경로:

`https://map.naver.com/p/favorite/myPlace/folder/7ebdcbab96084e56b8d4a01b9ab34af3/place/1463187795`

- 사용자 확인 이름: 스팀하우스 인덕원점.
- URL의 폴더 ID: 7ebdcbab96084e56b8d4a01b9ab34af3.
- URL의 장소 ID: 1463187795.
- 원래 URL의 지도 상태, 상세 경로, 시각 등 쿼리 값은 장소 ID 기록에서 제거한다.
- 이것은 사용자 선택 결과의 URL 관측이다. 주소·국가·목록 전체 소속·재조회 안정성의 증거로 확장하지 않는다.

## 이번 구현

- `core/detail.js`: 네이버 상세 URL을 ID와 표준 URL로 정규화하고, 정확한 폴더/장소 경로가 있으면 폴더 문맥을 기록한다.
- 팝업의 `네이버 상세 URL의 ID 읽기`: 최상위 상세 URL을 우선 읽고, 없으면 접근 가능한 프레임 URL에서 찾는다. 서로 다른 ID가 나오면 실패 처리한다.
- 장소 이름은 직접 입력한 값을 우선하고, 없으면 실기로 확인한 `이름 - 네이버지도` 탭 제목에서 읽는다. 출처를 user-entered/tab-title로 구분하고 일반 목록 제목은 이름으로 사용하지 않는다. 탭 제목에서 읽은 이름의 본문 대조는 미검증으로 표시한다.
- 확장 로컬에 detailReads로 보관하고 확장 관리 화면에 이름, 장소 ID, URL, 관측된 폴더 ID를 표시한다. 자동 JSON 다운로드를 실행하지 않는다.
- 상세 기록은 complete=false, membershipVerified=false, country=UNKNOWN이다. 계획기의 snapshots/places로 자동 전환하지 않는다.
- 관리 화면에서 확장 저장소와 localhost 데모 저장소가 별개임을 명시하고 이전 버튼명을 수정했다.
