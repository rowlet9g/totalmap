# 1단계: 네이버 장소 이름·주소 자동 읽기

작성일: 2026-10-06.

## 기존 커밋 푸시

사용자 요청에 따라 정상화 커밋 dc9f04b와 6f02148을 origin/main에 푸시했다. 구현 시작 시 로컬 HEAD와 origin/main이 6f02148로 일치했다.

## 구현 근거

사용자가 제공한 `totalmap-diagnostics-1791257092288.json`을 분석했다. 이 파일은 전체 목록 조회가 아니라 선택한 장소 상세 홈의 DOM 진단이다.

- 상세 iframe URL 경로: `https://pcmap.place.naver.com/place/1463187795/home`.
- 이름: 스팀하우스 인덕원점.
- 상세 이름 필드: `.place_pcmap_detail [role="main"] .place_section .V4UO6 > span.IY7ZX`.
- 보조 제목: `header[role="banner"] h1.bh9OH`.
- 주소 정보 행: `[role="main"] .place_section_content .O8qbU` 중 `strong.X2oNY > span.place_blind`의 텍스트가 정확히 `주소`인 행.
- 해당 행의 주소 필드: `a.PkgBl > span.pz7wy`.
- 상세 주소: 경기 안양시 동안구 인덕원로 19-2 1층.
- 이전 목록 진단의 지번 주소와 표현이 다르므로 원문과 출처를 보존한다. 이 단계에서는 도로명/지번 상호 변환이나 서비스 간 매칭을 수행하지 않는다.

## 기능

1. 장소 상세 홈에서 팝업의 `네이버 장소 이름·주소 읽기`를 실행한다.
2. 접근 가능한 프레임 중 pcmap.place.naver.com의 상세 홈에서 확인된 이름·주소 필드만 읽는다. 전체 본문, 리뷰, 메모, 이미지 URL, React 객체는 이 읽기 함수에서 수집하지 않는다.
3. 상세 URL의 ID, 선택한 탭의 ID/경로/제목, 필드 이름의 일치를 검사한다.
4. 성공한 기록은 기존 detailReads에 추가하고 관리 화면에 이름·ID·주소·출처를 표시한다.
5. 전체 목록 소속과 국가는 아직 판별하지 않았으므로 complete=false, membershipVerified=false, country=UNKNOWN을 유지한다.

기존 `네이버 상세 URL의 ID 읽기` 버튼도 유지한다. 자동 이름·주소 읽기가 실패한 경우 ID-only 기록과 자동 필드 성공 기록을 구분할 수 있다.

## 실패 처리

- 확인된 DOM 구조가 바뀌거나 필드가 없으면 실패로 표시한다.
- 다른 주소 라벨, 길 안내, 저장 폴더 텍스트를 주소로 사용하지 않는다.
- 다른 장소 ID, 이름 불일치, 여러 상세 영역/주소 행, 프레임끼리 충돌하면 저장하지 않는다.
- 읽는 동안 탭/장소/제목이 바뀌거나 확장 저장에 실패하면 성공으로 보고하지 않는다.
- 홈 외 리뷰/메뉴 페이지는 아직 지원하지 않는다. 접근 권한이나 로딩이 부족하면 상세 홈에서 다시 확인한다.

## 검증

- 사용자 상세 진단으로 실제 이름·주소 구조를 확인했다.
- 최소 DOM fixture는 위 관측된 필드 계층을 보존하고 민감한 전체 진단 파일을 커밋하지 않는다.
- 테스트는 정상 읽기, 확인된 선택자 변경, 잘못된 라벨, 숨겨진/누락/중복 필드, 제목 불일치, ID 불일치, 탭 이동, 저장 실패를 검사한다.
- 1단계 구현 검증에서 테스트 69개와 문법/manifest 검사가 통과했다.
- 사용자가 Whale에서 Totalmap을 새로고침하고 스팀하우스 인덕원점 상세 홈에서 새 버튼을 실행한 뒤, 이름과 주소가 정상 표시된다고 확인했다. 이 표본의 이름·주소 자동 읽기→확장 저장→관리 화면 표시를 실제 사용으로 검증했다. 다른 장소 및 반복 조회의 성공까지 확대해서 표현하지 않는다.
